## 1. 作业要求与验证方法

补充的 TTS 播放期采集问题见 [dev 说明第 9 节](dev-跨final合并与任务规划.md#9-tts-播放期间麦克风被抑制2026-09-14)：原始采集、RTP、ASR 发送、识别正文与轮次状态分别核对；耳机模式下两条真人短句在 TTS 播放期间返回完整 final。页面与原生虚拟麦克风专项通过；直接云 ASR 的低音量探针仅 2/3，按失败记录。该专项不与前述 98 例文本和四媒体场景混算，也不宣称所有设备的双讲或物理回声问题均已通过。

| 要求或风险 | 验证方法与判定依据 | 证据及范围 |
| --- | --- | --- |
| AI 播放时仍在接收用户语音 | 在旧轮 `speaking` 与取消之间收到新句的 ASR partial/final，并检查双向 RTP、下行非零能量 | 第 6 节真实媒体时间线；仅看累计包数不足以证明同时在线 |
| 疑似插话先 duck，不能立即硬切 | 解码服务端输出，比较 RMS；确认前播放队列继续消耗、旧 context 未取消，误触发后同轮恢复 | `TestDuckingReducesServerAudioAndContinuesPlayback`；实际幅度约为原来的 50% |
| 完整打断闭环 | 检查 duck、true、取消旧轮、清音频、切 epoch、新任务执行；对仍活跃的 LLM/TTS 分别断言 context 取消 | 第 6 节真实链路加并发单元测试，不用页面“已停止”代替后端验证 |
| 等待完整输入后回答 | 生产 `AcceptASR` 先完成跨 final 收集才允许确认或规划；旧 `Accept` 兼容路径另测 partial 预留新轮、final 前不启动生成 | `TestMergedFinalsReachPlannerOnceAndAllowLongFirstSentence`；旧入口用 `TestFullClosedLoopStartsNewGenerationOnlyAfterFinal` |
| 跨 final 与补充条件不重复回答 | 原始来源 ID 合成一条输入；超过短窗口但未派发的故事主题通过关系判断合并 | 第 6.6 节；独立问题 false 时保留两条 |
| 复合任务有序执行并完整取消 | 各步最后 RTP 发送后推进，整份计划后处理缓存；true 取消当前、剩余步骤及旧缓存 | 第 6.7 节；步骤与 epoch 同时关联 |
| 误触发与恢复 | 不稳定 partial、VAD 无文本、ASR 故障恢复音量；语气词、否定、引用由语义分类判 false | 自动测试覆盖控制逻辑和固定文本，尚缺系统性的真人回声/咳嗽样本 |
| 旧轮不能复活 | 清除待播帧，迟到音频被拒绝，旧 epoch 不再出现 speaking/completed；旧缓存输入 ID 不再派发 | 清缓存媒体场景加迟到结果单元测试 |
| 延迟、误打断、漏打断 | 固定预期标签与分母；分开统计直接响应、打断后响应、缓存等待 | 第 5、7 节；属于 Word 可选的体验验证，不声称线上准确率 |
| 失败案例与反思 | 保留历史错误、复现方式、修复和未覆盖边界 | 第 8 节；原始响应未留存时明确说明 |
| 演示过程记录 | 真人录制应关联播放、插话、duck、确认、停止和新轮回答 | [打断过程记录](打断过程记录.md)仍留空，本文自动化日志不替代待补录制 |

Word 建议的半双工/全双工、硬切/两阶段对照属于可选体验对比。目前没有控制变量的 A/B 结果；早期 20% duck 与当前 50% 的不同测试不构成对照实验。

## 2. 测试分层与替身边界

| 层次 | 输入和依赖 | 可以证明 | 不能单独证明 |
| --- | --- | --- | --- |
| Go 单元与组件测试 | 构造 PCM/ASR 事件、可控时钟、内存执行器或本地 HTTP/WebSocket 服务 | 取消传播、队列边界、协议解析、状态迁移、迟到结果隔离 | 云模型语义正确率、真实 ASR 和耳机听感 |
| 固定文本分类 | 固定文本、历史、当前工具和 partial/final，调用生产 DeepSeek 客户端 | 有序规划、打断/补充关系标签与输出协议的回归 | ASR、合并调度、动作内部重试、物理播放停止 |
| 真实媒体闭环 | 固定 WAV 经 WebAudio 虚拟麦克风进入浏览器；实际 WebRTC、腾讯 ASR、DeepSeek、腾讯流式 TTS | 真实云端识别、判定、取消、缓存和新轮下行的联动 | 真人麦克风、外放回声、物理耳机尾音 |
| 浏览器 UI 回归 | Playwright 加载页面，注入控制事件和长文本 | 控件、错误展示、静态图片、非空波形、响应式排版 | 云服务成功、真实录音或声学波形质量 |

媒体测试运行在 localhost，物理输出静音以避免外放反馈。输入是预合成语音，但处理链中的 ASR、意图判定和 TTS 都实际调用云服务；工具执行效果按当前需求以重复十次台词模拟，没有连接游戏客户端。单元测试中的替身仅用于可控地制造取消、拒绝和迟到回调，未冒充真实媒体演示。

## 4. 如何做回归

### 4.1 本地快速回归

在项目根目录执行。Go 已加入 PATH 时直接用 `go`；本机安装位置为 `E:/go/bin/go.exe`。

```powershell
& 'E:/go/bin/go.exe' test -count=1 ./...
& 'E:/go/bin/go.exe' vet ./...
node --test scripts/acceptance_stats.test.cjs
```

`-count=1` 强制重新执行，避免把缓存结果误作本次运行。预期 Go 各含测试包为 `ok`、vet 退出 0 且无诊断、Node 为 7 pass / 0 fail。命令入口显示 `[no test files]`，signaling 已有诊断端点测试。未启用 CGO/C 编译器，未运行 race 检测。

UI 回归需要已启动的应用服务、Node.js 18 以上、Chrome 与 Playwright。脚本注入页面状态，不建立麦克风会话，不调用云接口。

```powershell
npm install --prefix bin/browser-check --no-save playwright
$env:NODE_PATH = (Resolve-Path 'bin/browser-check/node_modules').Path
$env:DEMO_URL = 'http://localhost:8080'
node scripts/verify_ui.cjs
```

预期返回 `passed:true`、五种宽度和 `controls:22`，截图保存到 `bin/ui/`。Chrome 路径不同可设置 `CHROME_PATH`。

### 4.2 完整固定验收

需要 `.env` 中有效的腾讯与 DeepSeek 配置、匹配引擎的 ASR 额度及 TTS 额度，会实际消耗云服务资源。沿用上面的浏览器依赖设置后执行：

```powershell
$env:GO_BIN = 'E:/go/bin/go.exe'
node scripts/verify_acceptance.cjs
```

默认运行 98 例 × 3 次文本分类和 12 场景 × 1 次媒体。脚本编译当前源码，自动选择空闲端口启动独立服务，结束时关闭；不需要替换正在使用的 8080 服务。输入 WAV 缺失时自动合成，已有素材复用。

```powershell
node scripts/verify_acceptance.cjs --text-only --repeat 1
node scripts/verify_acceptance.cjs --repeat 5 --media-repeat 3
```

- **全双工**：旧轮已开始播放且尚未取消时，`:2` 和 `:3` 仍有 ASR 结果。浏览器累计接收 1791 包、286560 字节，发送 1798 包、286400 字节，接收音频能量约 2.4743。包数和能量佐证媒体有效，时间线证明播放过程中上行仍在工作。
- **后端取消**：存在旧 epoch 的取消事件、250 个待播帧被清除、工具取消及新 epoch 转移；后续旧轮没有 speaking/completed。250 × 20ms = 5000ms 是丢弃的待播内容长度，不能解释成听到的停止延迟。
- **缓存确实丢弃**：旧问题 `:2` 进入过缓存，却没有后续 `input_dispatched`；被派发的是重新说出的 `:4`。只比较问题文本会把新问题误认成旧缓存复活，必须关联输入 ID。

- **final 的先后关系**：这次 true 到达时 final 已有，所以新轮直接处理完整句。partial 确认早于 final 时的“先预留、再等待”由独立状态机测试验证，不能声称在本段真实录音中观察到了该顺序。

来源：[完整基线的延后种地记录](evidence/acceptance-20260912/media/deferred-wait-1/home-wait-voice.json)，日期 2026-09-12、ASR `8k_zh`。UTC 时间链为：

`09:10:51.487 water speaking` → `09:10:53.937 final 等一下再去种地` → `09:10:54.436 interrupt=false` → `09:10:54.437 input_buffered` → `09:10:54.438 speaking reason=intent_deferred` → `09:11:10.668 water completed` → `09:11:10.670 input_dispatched` → `09:11:11.350 plant running` → `09:11:30.108 plant completed`。

### 6.3 严格 JSON、拒绝与兜底 false

生产链路为：DeepSeek JSON mode 及固定 prompt → 本地完整解析和字段校验 → 合法布尔结果，或错误兜底 false → `intent_result` 与日志 → 恢复播放、final 入缓存。模型输出文本不直接交给 TTS，也不从夹带文字的正文中抽取 JSON 来授权打断。

`TestIntentJSONIsStrict` 明确包含 `好的，{"interrupt":false}`，并覆盖围栏、重复键、额外字段、字符串布尔值和 null 等；这些响应不属于合法 false。`TestIntentRequestAndProviderValidation` 检查截断结束状态和非法正文的错误脱敏，`TestIntentErrorDefersInsteadOfInterrupting` 验证错误路径实际保留旧轮和输入。

事件携带 `interrupt=false fallback=true status=error`，reason 为 `invalid_output`、`timeout` 或 `request_failed`；日志记录 false、fallback、原因、epoch、输入 ID 和请求耗时，以区分异常和正常 false。统计脚本将异常算严格失败；即使它的 false 兜底碰巧符合预期，也不能提高通过率。这是协议防线与回归断言，不是“prompt 能绝对约束模型”的承诺。

2026-09-14 已在共享[严格布尔客户端](../internal/llm/intent.go)补齐 `message.refusal` 检查，`TestContinuationRequestAndRefusalOverrideValidBoolean` 分别覆盖打断与补充关系的拒绝字段和合法 true 同时出现。两者均返回错误、由调用方明确兜底 false；文本式拒绝也因不符合 JSON 契约而拒绝。此处证明协议拒绝路径，不代表语义标签永远正确。

### 6.4 ASR 资源包问题的定位链

现象是页面反复显示识别连接失败，购买资源包后仍失败。诊断从服务端 ASR 4004 及实际请求引擎 `8k_zh` 入手，与用户购买的“大模型 2.0 实时语音识别”资源包类别对照，定位到计费类别不匹配。配置调整为 `16k_zh_en_2.0` 后还必须适配 V2 结果结构，不能只改引擎字符串。

验证分三步：协议测试确认签名包含 `input_sample_rate=8000`、上行仍为 3200 字节/200ms PCM16LE，V2 final 快照不会重复提交；4004 故障注入确认握手和识别阶段都有脱敏且可操作的提示；真实 V2 媒体记录确认连接成功并持续产出 partial/final，最终完成切换和回答。UI 回归另外检查错误原因可见，识别状态恢复后旧提示清除。

这支持已修复的引擎/协议和提示路径；不等同于测试了所有计费、鉴权或并发错误，也不保证今后账户额度不会再次耗尽。

### 6.5 故事请求与实际回答的证据

本次新增 `context_test.go` 验证 completed/cancelled/failed 三种实际状态进入规划和回答上下文；固定文本验证祈使句式的故事、笑话、解释、翻译属于问答，明确停止/优先回答才授权打断。模型 JSON 合法不等于语义正确，原问题就是合法 true 的误判。

真实媒体用 `scripts/verify_story.cjs --deferred` / `--interrupt` 经固定麦克风音频调用完整云链路，关联 `input_merge`、`intent_result`、缓存或取消、旧工具终态、新 `general_qa`、`response_context`、最终 `response_text` 和故事期间新增下行音频能量。必须阅读正文，不能只看到 `general_qa completed` 就算用户请求已满足。完整用例、原始失败及复测结果见 [dev 扩展第 7 节](dev-跨final合并与任务规划.md#7-故事请求误打断与历史状态修复2026-09-14)。

## 7. 统计口径与结论边界

| 指标 | 计算口径 |
| --- | --- |
| 严格通过率 | 合法且标签正确的次数 / 计划次数；未执行、非法响应、超时均非通过 |
| 误打断率 | 预期 false、有效决策却为 true 的次数 / 已执行的预期 false 次数 |
| 漏打断率 | 预期 true、有效决策却为 false 的次数 / 已执行的预期 true 次数；错误兜底 false 计入漏判 |
| 请求错误率 | 请求错误次数 / 已执行次数；另保留只统计合法响应的混淆矩阵 |
| P50 / P95 | nearest-rank：排序后第 `ceil(p × N)` 项；0ms 有效，无样本为 null |
| final 到首音频 | final 进入服务端轮次管理器至首个非静音 RTP 帧发送，按每轮最后已知累计指标去重 |
| 句末到首音频 | ASR 句末偏移映射到输入包抵达服务端的时间，再计算至首个非静音 RTP 发送；缺失映射不编造数值 |
| `speech_to_duck_ms` | VAD 回推起点或 ASR 文本到达至首个非零降音帧发送；每轮只保留最近已知值 |
| 确认到取消 | 浏览器接收 true 与 response_cancelled 控制事件的时间差，含调度和事件传递影响 |

固定重复并非独立用户样本，“180 次分类全对”只说明这套输入的该次回归通过。文本 false/true 不直接等于真实语音的误/漏率，ASR 误识别及触发时机仍可能影响结果。旧基线 `speech_to_duck` 的直接响应 P50/P95 为 9/18ms，V2 单例中有 0/2ms；这些可能是 ASR 后再次降音的局部间隔，不能写成“用户开口几毫秒内系统就完成反应”。

`direct`、`interrupted`、`deferred`、`planned` 必须分开；缓存及后续计划步骤保留原 final 时间，等待不应混入即时响应性能。补充关系 true/false 另列统计，不进入打断混淆矩阵。`speaking` 事件也可能对应先发送的静音，首音频必须看非静音帧指标。当前指标均未量化从麦克风采集到耳机实际出声的总时延，事件层旧轮不恢复不等于已测出物理尾音长度。

## 8. 失败案例、反思与待验证项

| 问题 | 已有证据与修复 | 反思及边界 |
| --- | --- | --- |
| “等一下再去种地”误停浇水 | [历史文本](evidence/home-wait-classifier.json)与[语音](evidence/home-wait-voice.json)；现生产入口增加跨 final 合并，第 6.6 节有真实两段 final 证据 | 不能按停止前缀硬切；有界合并增加等待，超窗且已开始的输入不能事后撤回 |
| 故事与主题被回答两次 | 缓存派发前增加补充关系分类，主题 true 合并，独立问题 false 分开；见第 6.6 节 | 单靠延长 ASR 静默窗口不能覆盖长任务期间的补充；只合并尚未执行输入 |
| 复合任务提前推进或打断后余项恢复 | 按最后音频发送成功推进，取消整份计划与缓存，迟到结果校验 epoch；见第 6.7 节 | 文本生成结束不是执行结束；真实游戏 SDK 接入后仍需单独设计动作取消回执 |
| 首次“干的不错”提示任务没能启动 | [复现调查](evidence/home-praise-classifier.json)、[媒体](evidence/home-praise-voice.json)、[六工具协议验证](evidence/home-strict-classifier.json)；构造历史复现 schema 元信息进入参数，改用 strict 空对象加本地校验 | 原次完整模型返回未保留，只能说复现了同类协议错误；成功重试不能掩盖协议失败，首次夸赞媒体要求零重试 |
| 打断后旧缓存继续被回答 | [专项](evidence/home-clear-buffer-voice.json)及本次 V2 时间线；确认时清旧 final/草稿/请求并隔离迟到输入 | 只清音频不足以满足用户的“打断后缓存也不要”；需同时核对输入 ID 和 epoch |
| 买了 ASR 包仍识别失败 | 第 6.4 节计费类别、协议测试及真实连接恢复证据 | UI 应显示安全错误码和实际引擎，不能把额度、网络和鉴权都折叠成连接失败 |
| 未确认 duck 恢复后又降音 | V2 时间线在 03:16:46.316 恢复、47.202 再降音 | 当前 watchdog 与异步意图结果的交互会出现音量往返；可继续评估判定期间的恢复时机，同时保留噪声下的恢复上限 |

交付后的进一步验证应在统一源码快照上重跑当前十二场景，补充真人耳机采集样本，覆盖“停止”、普通问题、“嗯/啊”、咳嗽、背景声、短暂停顿和首音频刚开始时插话。回声改造目前暂缓，外放场景保留待验证。用同一批输入保留成功与失败样本、输入 ID、epoch、控制日志及录音时间标记，才能区分 ASR、合并等待、语义判定、取消调度和播放缓冲问题。
