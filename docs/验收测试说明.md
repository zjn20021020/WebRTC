# 固定验收集与自动统计

## 验收范围

固定文本集为 [cases.json](../testdata/acceptance/cases.json)，版本 `home-acceptance-v1`，共 60 例：18 个动作分类、42 个打断分类。每例使用稳定 ID、分类标签、原始输入和明确预期；夸赞回归保留容易触发历史参数故障的上下文。覆盖四种农务的全部 12 种交叉切换、同类动作、延后安排、普通/优先问答、夸赞、否定、引用、语气词和完整/不完整 partial。

文本层直接调用生产的 DeepSeek 分类客户端和严格协议校验，每个样例每轮只有一次请求，动作上限 5 秒、打断上限 2 秒。它不经过麦克风和 ASR，也不代表 partial 已经过生产调度门槛。动作格式重试、实际取消、缓存派发和十次播报通过下一层验证。

固定媒体集为 [media.json](../testdata/acceptance/media.json)，版本 `home-media-v1`：

| 场景 | 关键验收点 |
| --- | --- |
| deferred-wait | 浇水时说“等一下再去种地”，保持浇水十次，完成后种菜十次 |
| first-praise | 种菜中只说一次“干得不错”，缓存后贴贴十次；无格式重试或任务失败 |
| explicit-replacement | “先别浇水了，去施肥”取消旧轮、清待播，后续夸赞延后执行 |
| direct-switch | 种菜中直接“去施肥”切换，普通问题不打断施肥 |
| discard-old-buffer | 确认打断丢弃旧问题，旧问题不复活，新提出的问题仍正常缓存和回答 |

媒体层复用 [verify_home.cjs](../scripts/verify_home.cjs)，固定合成语音经 WebAudio 虚拟麦克风进入实际 WebRTC、腾讯 ASR、DeepSeek 和腾讯流式 TTS。物理输出静音，未替换识别结果或轮次管理器。每次检查上下行 RTP、非零接收音频、duck、工具顺序、取消后无旧轮恢复，以及场景要求的十次台词与缓存行为。

## 一键运行

需要 Go、Node.js 18 或以上、Chrome、Playwright，以及根目录 `.env` 中可用的云凭证。会实际调用付费云接口。默认运行 3 轮文本与 1 轮五个媒体场景，顺序执行，避免同一服务并发会话互相关闭。

```powershell
# Playwright 已能被 Node 加载时可略过安装与 NODE_PATH。
npm install --prefix bin/browser-check --no-save playwright
$env:NODE_PATH = (Resolve-Path 'bin/browser-check/node_modules').Path
$env:GO_BIN = 'E:/go/bin/go.exe'
node scripts/verify_acceptance.cjs
```

如果 Go 已在 PATH，可省略 `GO_BIN`；Chrome 路径可用 `CHROME_PATH` 覆盖。脚本从当前源码构建独立服务，自动选择本机空闲端口，测试完关闭，运行中的 8080 服务无需重启。缺少输入 WAV 时自动调用原有素材生成命令并显式用音色 `1001`，已有素材复用；本次所用 WAV 的 SHA256 写入报告，TTS 输出仍使用应用配置音色。不同机器重新合成的 WAV 不保证逐字节相同，应比较哈希并说明输入来源。

```powershell
# 快速检查分类，仍真实调用 DeepSeek。
node scripts/verify_acceptance.cjs --text-only --repeat 1
# 更长的重复验收。
node scripts/verify_acceptance.cjs --repeat 5 --media-repeat 3
# 不调用云服务的统计逻辑测试。
node --test scripts/acceptance_stats.test.cjs
```

单独运行 Go 文本工具也可：`go run ./cmd/verify-acceptance -repeat 3 -output bin/acceptance-text.json`。输出是原始分类结果；一键入口另外生成汇总与媒体证据。

## 输出与判定

每次运行创建 `bin/acceptance/<UTC时间>-<进程ID>/`，不覆盖旧证据。目录包含固定集快照、`text-results.json`、`summary.json`、`report.md`、模型调用及服务日志、每个媒体场景的 JSON 和截图。报告保存提交号、源码内容 SHA256、验收集 SHA256、输入音频 SHA256 和服务实际音色，便于区别不同版本和素材。提交号为启动时的 HEAD，尚未提交的源码由内容摘要区分。

文本每次调用结束立即保存结果，错误不会中断后续样例。语音场景失败也保存已有事件和页面截图，继续其他场景。预检或进程失败会留下报告，并将未执行样例列为缺失；不能把空结果报成通过。通过返回退出码 0；不符合预期、缺少计划样例或运行错误返回非零。文本要求所有计划样例通过，媒体要求所有场景功能断言通过；媒体中的兜底与重试次数单列，首次夸赞场景额外要求零重试。

分类器的格式/超时错误不能通过改预期值或删除样例变成绿灯。产品规则确实变化时，应同时更新用例、版本号和规则文档。修复后保留失败报告，再运行新批次，不覆盖历史。

## 指标口径

| 指标 | 计算 |
| --- | --- |
| 严格通过率 | 合法响应且与预期相同的次数 / 计划次数；错误和未执行都不算通过 |
| 请求错误率 | 协议失败、超时、请求失败次数 / 已执行次数 |
| 误打断率 | 预期 false、有效决策为 true 的次数 / 已执行的预期 false 次数 |
| 漏打断率 | 预期 true、有效决策为 false 的次数 / 已执行的预期 true 次数；包括错误后的 false 兜底 |
| P50 / P95 | 对非负有效耗时排序，取 `ceil(p × N)` 对应样本；无数据时为 null / `--` |
| 分类波动 | 同一固定样例不同轮次的标签或错误类型不一致 |
| 旧轮恢复 | 取消后同一 epoch 再出现 speaking 或 completed；不等于耳机缓存尾音 |

JSON 同时给出合法响应混淆矩阵与包含 false 兜底的有效决策矩阵。即使异常兜底 false 恰好符合预期 false，严格分类结果仍记失败。主要请求延迟包含错误和超时，另列合法响应耗时，避免只看成功调用掩盖长尾。每个统计都有样本数；重复相同文本不能当成独立的真实用户样本。

媒体首字/首音频指标在每场运行中按 `response_epoch` 合并累计快照，每轮每项只保留最后一个已知值。分成 `direct`（直接响应）、`interrupted`（确认打断后的新轮）、`deferred`（缓存派发）统计，缓存时间不混进直接响应延迟。`speech_to_duck_ms` 每轮只取最近一次已知值，不宣称统计了每一次疑似插话。

首音频指服务端首个非静音 RTP 帧发送。确认到取消指浏览器接收到对应控制事件的间隔，并非用户开口到耳机静音；浏览器事件受到传输与调度影响。`speech_to_duck_ms` 的起点可来自 VAD 回推或 ASR 文本到达，不能统一解读为真人开口时刻。声学回声、咳嗽、真人长停顿、多个说话人、跨 final 合并和物理耳机尾音不在这次自动验收范围内。

## 首次完整基线

2026-09-12 运行一键入口，结果归档于 [验收报告](evidence/acceptance-20260912/report.md)。60 例各重复 3 次，动作 54/54、打断 126/126；误打断 0/60、漏打断 0/66，分类请求无错误。动作请求 P50/P95 为 906/1216ms，打断请求为 802/919ms。五个真实语音场景全部通过，无旧轮恢复事件、动作/打断兜底或动作重试。

直接响应的 final 到首音频发送为 P50 1608ms、P95 1788ms（5 轮）；打断后新轮为 2520/2555ms（3 轮）。缓存派发耗时单列，不能据此把主动等待判为模型变慢。以上是这批固定输入的基线，不是线上 SLA。

统计测试覆盖空数据、0ms、nearest-rank、false 兜底不算成功、缺失记录、误/漏率分母、重复记录拒绝、指标快照去重和缓存等待分组。另用无效构建工具路径与不可访问浏览器地址注入运行失败，确认报告为失败并保留事件/截图；这些是故障注入验证，不混入真实云基线。`go test ./...`、`go vet ./...` 与四项 Node 统计测试均通过。
