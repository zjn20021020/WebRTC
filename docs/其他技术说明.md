## 角色 Skill 与工具接口

[迪莫 SKILL.md](../internal/home/skills/dimo/SKILL.md)以 `go:embed` 编入程序，在通用问答的 system 消息中加载，约束身份、中文短句语气和事实边界。这是应用的运行时角色文件。它不持有密钥或执行权限，修改后需要重新编译或重启 `go run`。

工具定义见 [home.go](../internal/home/home.go)：`water`、`plant`、`harvest`、`fertilize`、`affection` 和 `general_qa`。默认 `VoiceExecutor` 将五类动作的固定台词逐句输出十次；`general_qa` 由轮次管理器调用角色问答。种菜、种地、种田归为同一动作。

`Executor.Execute(ctx, Request, speak)` 是预留接口，`Request` 包含调用 ID、轮次和原始请求；`NewWithExecutor` 可注入其他执行器。返回仅代表台词生产结束，`tool_status:completed` 等待本轮音频全部发送后才触发。未来接真实动作还需要幂等、取消回执和不可逆效果说明，目前未实现。

## 分类与响应协议

### 动作分类

[action.md](../internal/llm/prompts/action.md)独立于口语角色指令。请求使用原生 `tools`、`tool_choice:required`、非思考模式、温度 0、128 token 上限。每句 final 最多执行一个工具；“先浇水再施肥”等复合计划、方法询问、引用、否定和不支持的操作由 `general_qa` 回应或澄清。

官方 DeepSeek 地址的动作分类单独请求 `/beta/chat/completions`，六个函数启用 `strict:true`，参数 schema 为 `properties:{}`、`required:[]`、`additionalProperties:false`。问答与打断判定保持原地址，自定义网关不自动改写为 Beta。依据：[Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion)、[Tool Calls](https://api-docs.deepseek.com/guides/tool_calls)。

供应商 strict 不替代本地校验：必须单一 choice、`finish_reason:tool_calls`、无正文与拒绝、恰好一个有 ID 的 function call、函数在白名单中，arguments 是完整空对象 `{}`。正文里的 JSON 不被当作工具调用提取执行。

格式异常可在原 5 秒总期限内重试一次；拒绝、供应商错误、网络失败和超时不做格式重试。第二次仅添加固定协议修正说明，不回传被拒绝的模型输出。最终失败时播报“小洛克，这次任务没能启动，请再试一次。”。日志与事件 `action_retry`、`action_result` 用 `validation` 区分多调用、额外正文、截断、非法参数等。

### 打断分类

[interruption.md](../internal/llm/prompts/interruption.md)要求只输出 `{"interrupt":true}` 或 `{"interrupt":false}`。请求采用 JSON mode、非思考模式、温度 0 和最多 32 个 token；本地 token 解析拒绝额外正文、代码围栏、重复键、额外字段、字符串布尔值、null、大写 True/False 和截断。

每个请求最长 2 秒。异常保守返回 false，`intent_result` 携带 `fallback:true`、`status:error` 和 `invalid_output`、`timeout` 或 `request_failed`，与正常 false 区分；判断文本不送入 TTS。

同句最多三个 partial 请求，发起间隔至少 500ms；final 不受 partial 限流约束。文本补长或改写后取消旧请求并增加版本。等待类 partial 等 final 再判断；关键词仅决定请求时机，不能绕过 LLM 直接授权硬打断。尚在最小 duck 窗口的 true 可被新文本撤回，已实施的旧轮取消不能复活。

直接切到不同农务默认 true；明确延后优先于隐含立即切换，明确停止当前活动优先。重复同类动作、夸赞、亲密请求和普通问题默认 false；转到问答需要明确暂停或优先回答。从问答或亲密动作直接要求农务也判 true。细例见 [实验报告](作业任务说明.md#第二阶段确认与切换)。

## 音频与队列实现

上行 PCMU 解码为 8kHz 单声道 PCM16LE，按 3200 字节 / 200ms 送入腾讯实时 ASR。服务端对 WebSocket 请求执行 HMAC-SHA1 签名，保留语气词。`TENCENT_ASR_MODEL` 支持两种配置，省略时兼容旧版 `8k_zh`；当前本机及配置模板选择 `16k_zh_en_2.0`。

| 引擎 | 计费资源包 | 音频及结果协议 |
| --- | --- | --- |
| `8k_zh` | 普通实时语音识别 | 8kHz PCM，600ms 静音断句；`result.slice_type` 0/1 为 partial、2 为 final |
| `16k_zh_en_2.0` | 大模型 2.0 实时语音识别 | `input_sample_rate=8000` 由云端升采样；`result_mod=1`、`sentence_strategy=0`；`sentences.sentence_list` 的 `sentence_type` 0 为 partial、1 为 final |

新版使用最小语义分句，不声称仍采用旧引擎的 600ms 阈值。两种协议均使用云会话 ID 加句子序号作为输入 ID，独立于回答轮次；V2 重复快照中的已定稿句子会被忽略，毫秒时间戳保持原语音时长，不把输入帧大小误改为 16kHz 的 6400 字节。依据：[实时识别 V2](https://cloud.tencent.com/document/product/1093/131127)、[官方 Go SDK V2 结果结构](https://github.com/TencentCloud/tencentcloud-speech-sdk-go/blob/master/asr/realtimerecognizer_v2.go)、[计费概述](https://cloud.tencent.com/document/product/1093/35686)。

ASR 使用独立有限队列，积压超过约 2 秒时停止该次识别并报告错误，上行接收和下行播放继续。ASR 不可用时解除未确认 duck 并禁用后续 VAD 降音；当前不自动续接识别任务，可断开后重新连接。协议见[实时语音识别](https://cloud.tencent.com/document/product/1093/48982)。

2026-09-13 的连接失败来自普通引擎额度耗尽（4004），购买的大模型 2.0 资源包不能抵扣该类别。`ProviderError` 保留安全错误码，`asr_error` 同步 `model`、`code`、分类状态和本地固定解释；页面显示原因并写入日志。4002/4003/4004/4005/4006 分别对应鉴权、未开通、额度、欠费和并发限制，原始供应商 message 与带签名 URL 不进入页面或日志。不会自动换到其他计费类别，也不会替用户开启后付费。

TTS 运行时使用 `wss://tts.cloud.tencent.com/stream_ws`，分片随到随转换为 PCMU。跨分片保留未完成的 PCM 样本和 160 字节 RTP 帧，只有句尾不足一帧时补静音。文本每段最多 100 字符，待播最多 250 帧；背压限制合成推进。取消上下文会关闭云端 WebSocket，旧轮入队与发送都受 epoch 校验。

`TextToVoice` REST 方法仅用于生成固定测试输入，不是运行中 TTS 的回退路径。没有将取消本地请求描述成供应商内部计算或计费必然立即停止。

## 文本缓存与生命周期

完整输入缓存最多 8 句、每句最多 2000 字符，按首次识别顺序处理。partial 只更新草稿；连续 15 秒未更新的未完成输入、或 ASR 结束时的草稿会释放。队列满显式提示“本句未收录”，重复 final 去重。

`confirmLocked` 先取出触发句，再清理其他缓存与草稿、取消关联意图请求、记住被丢弃句子 ID，然后取消旧轮并建立新轮。操作在同一把锁内完成。false、判定失败和未实施确认被撤回时不会清缓存。日志为 `cleared=true reason=interrupted inputs_dropped=N`，页面同步零计数；打断后新输入仍正常接收。

手动停止携带目标 `response_epoch`，迟到命令不能停止新轮；停止、断开均清待处理输入。单轮有 90 秒总期限。最近约 12 条对话消息供会话内上下文使用，完整发送结束的助手回答才进入历史。当前只支持一个浏览器会话。

## 音色与界面

默认腾讯音色为 `101016`（智甜，精品女童声），按用户希望清亮童声的反馈选择，用作迪莫近似配音，不是官方原声。音色通过 `TENCENT_TTS_VOICE_TYPE` 设置，与角色 prompt 独立；语速、音量保持供应商默认值，播放中的 50% duck 由服务端处理。依据：[音色列表](https://cloud.tencent.com/document/product/1073/92668)、[实时合成接口](https://cloud.tencent.com/document/product/1073/94308)。

```bash
go run ./cmd/tts-preview -out bin/tts-preview.wav
go run ./cmd/tts-preview -voice 502007 -out bin/voice-zhixiaohu.wav
```

试听工具通过实际流式客户端合成，保存 PCM16 → PCMU → PCM16 转换后的 WAV，并输出首包、长度和 RMS。智甜单次试听首包 430ms、音频 7798ms、RMS 3104；首版 `603002` 软萌心心因听感偏沉被替换，其历史结果不作为新音色的试听结果。

家园界面使用官方原野背景、迪莫贴纸与 Lucide 图标，绿白工作台保留连接、断开、麦克风 RMS/波形、播放器、字幕、回答、轮次、工具、打断状态、待回答数量、停止按钮、延迟和日志。图片为本地 WebP，桌面双栏、手机纵向，支持长文本滚动与减少动画偏好。素材只是主题呈现，不代表游戏家园实景已核实。来源及许可见 [SOURCES.md](../web/assets/SOURCES.md)。

`node scripts/verify_ui.cjs` 检查 1440、1024、768、390、320px 的 22 个控件、图片、波形像素和长文本排版，包含新增的识别错误详情及重连后清除提示。历史界面截图为 [桌面](evidence/home-ui-desktop.png)、[手机](evidence/home-ui-mobile.png)；静态文件修改后刷新页面即可。

## 延迟观测与自动验收

用例与回归方法、分版本测试结果，以及全双工和完整取消的证据解读集中在 [测试情况与证据链分析](测试情况与证据链分析.md)。本节保留统计实现与命令索引。

### 测量口径

| 字段 | 边界 |
| --- | --- |
| `speech_end_to_first_text_ms` | ASR 句末音频到达服务端至首个正文或工具台词 |
| `speech_end_to_first_audio_ms` | 同一句末至首个非静音 RTP 帧发送 |
| `asr_final_to_first_text_ms` | final 进入轮次管理器至首个正文或工具台词 |
| `asr_final_to_first_audio_ms` | final 进入轮次管理器至首个非静音 RTP 帧发送 |
| `speech_to_duck_ms` | VAD 回推起点或 ASR 文本到达至首个非零降音帧发送 |

ASR 音频偏移通过最近约 120 秒的输入包时钟映射为服务端时间。缺失或超出映射范围的指标保持空值，页面显示 `--`。指标不包含麦克风采集、上行网络、浏览器抖动缓冲和耳机输出延迟。缓存保留 final 原始时间，因此缓存轮次的响应指标包含有意等待。

### 固定验收集

[cases.json](../testdata/acceptance/cases.json)版本 `home-acceptance-v1`，共 60 例：18 个动作、42 个打断分类。稳定 ID 固定文本、历史、当前工具、partial/final 和预期，覆盖农务交叉切换、同类动作、延后、问答、夸赞、否定、引用与语气词。文本层每次只请求一次生产分类客户端，不包括 ASR、partial 调度门槛或动作内部重试。

[media.json](../testdata/acceptance/media.json)固定五个真实媒体场景：延后种地、首次夸赞、明确替换、直接切换、确认打断清旧缓存。合成语音经 WebAudio 虚拟麦克风进入真实 WebRTC 和云服务，物理输出静音；检查上下行、非零接收音频、duck、取消顺序、十次台词、缓存与旧轮不恢复。

### 运行验收

需要 Go、Node.js 18 或以上、Chrome、Playwright 和有效云凭证；会实际调用云接口。应用本身不需要 Node。

```powershell
npm install --prefix bin/browser-check --no-save playwright
$env:NODE_PATH = (Resolve-Path 'bin/browser-check/node_modules').Path
$env:GO_BIN = 'E:/go/bin/go.exe'
node scripts/verify_acceptance.cjs
```

Go 已在 PATH 时可省略 `GO_BIN`，Chrome 路径可用 `CHROME_PATH` 覆盖。默认 60 例各三轮、五个媒体场景各一轮，顺序执行。脚本从当前源码构建独立服务，自动选择空闲端口，完成后关闭，不影响运行中的 8080 服务。缺失输入 WAV 自动用音色 `1001` 生成，已有素材复用；输出仍用应用配置的音色。重新合成的输入不保证字节相同，报告保存实际文件哈希。

```powershell
node scripts/verify_acceptance.cjs --text-only --repeat 1
node scripts/verify_acceptance.cjs --repeat 5 --media-repeat 3
node --test scripts/acceptance_stats.test.cjs
go test ./...
go vet ./...
```

每次创建 `bin/acceptance/<UTC时间>-<进程ID>/`，保存 `report.md`、`summary.json`、固定集快照、逐例结果、日志和截图，不覆盖旧证据。提交号为启动时的 HEAD，源码、验收集与输入 WAV 另记 SHA256，区分未提交改动和素材变化。

文本逐条保存，单例失败后继续；语音失败保留已有事件和截图，并继续后续场景。错误或未执行不能算通过。文本要求所有计划样例合法且标签正确，媒体要求所有场景功能断言通过；首次夸赞额外要求无格式重试。总体通过退出码为 0，否则非零。

### 自动统计

严格通过率以计划次数为分母，请求错误率以已执行次数为分母。误打断率是预期 false 却有效判 true 的比例，漏打断率是预期 true 却有效判 false 的比例；请求异常按运行时 false 计入有效决策，但即使恰好符合 false 预期，也始终算严格分类失败。未执行项单列，不进入误/漏率分母。

JSON 保存合法响应及含兜底的混淆矩阵、分类别结果、逐样例波动与失败原因。P50/P95 用 nearest-rank，即排序后第 `ceil(p × N)` 项；0ms 有效，无样本返回 null。主要请求延迟包含错误与超时，另列合法响应耗时。

媒体按每次运行、每个 epoch 合并累计快照，每项只保留最后已知值。`direct`、`interrupted`、`deferred` 分开统计；缓存等待不混进直接响应。`speech_to_duck_ms` 每轮只保留最近一次已知值。确认到取消是浏览器控制事件间隔；旧轮恢复检查不等于物理尾音测量。

| 等一下再种地误切浇水 | 等待 partial 到 final 再判定，文本更新作废旧请求与未实施确认 | [文本](evidence/home-wait-classifier.json)、[语音](evidence/home-wait-voice.json) |
| 明确替换后任务没能启动 | 原次日志仅确认 invalid_output，未保存原始返回；分离角色与分类，增加限次修复和细分日志 | [文本](evidence/home-replacement-classifier.json)、[语音](evidence/home-replacement-voice.json) |
| 首次干的不错失败 | 构造历史复现 schema 元信息进入参数；启用 strict 空对象模式；不能认定新响应就是原次响应 | [文本](evidence/home-praise-classifier.json)、[语音](evidence/home-praise-voice.json)、[六工具](evidence/home-strict-classifier.json) |
| 去施肥必须先说别种菜 | 更新语义为不同农务默认切换，延后和普通问答仍缓存 | [文本](evidence/home-switch-classifier.json)、[语音](evidence/home-switch-voice.json) |
| 打断后旧问题继续回答 | 硬确认时清旧文本和草稿，保留触发句，迟到结果不可复活 | [语音](evidence/home-clear-buffer-voice.json) |

单项复现的命令组合如下。浏览器脚本要求已有测试服务；`DEMO_URL` 指定地址，单会话服务会关闭之前的连接。使用 `EVIDENCE_DIR`、`SCREENSHOT_DIR` 指向新目录，避免覆盖历史资料。

| 场景 | 文本工具参数 | 素材生成参数 | 媒体脚本参数 |
| --- | --- | --- | --- |
| 家园主场景 | `-suite home` | `-scene home` | 无 |
| 延后种地 | `-suite wait` | `-scene home-wait` | `--wait` |
| 明确替换 | `-suite replacement` | `-scene home-replacement` | `--replacement` |
| 首次夸赞 | `-suite praise` | `-scene home-praise` | `--praise` |
| 直接切换 | `-suite switch` | `-scene home-switch` | `--switch` |
| 清旧缓存 | `-suite switch` | `-scene home-switch` | `--clear-buffer` |

三类命令分别是 `go run ./cmd/verify-home`、`go run ./cmd/demo-fixtures`、`node scripts/verify_home.cjs`。通用问答 true/false 回归另有 `cmd/verify-intent` 与 `scripts/verify_intent.cjs`。

早期故事与噪声实验使用 20% duck 及旧文本规则，后续已经调整为 50% 与独立 LLM 判定。历史 [barge-in.json](evidence/barge-in.json)、[server-barge-in.txt](evidence/server-barge-in.txt)保留当时数据；[intent-barge-in.json](evidence/intent-barge-in.json)为后续语义版。早期原始声学失败样本未完整留档，不把它们说成当前版本的系统性声学验收。
